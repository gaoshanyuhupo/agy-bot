# Live Browser (`live-browser` — Telegram Real-Time View & Human Takeover)

`live-browser` (`~/.local/bin/live-browser` -> [scripts/live_browser_ctl.py](./scripts/live_browser_ctl.py)) connects to the persistent local `agy-live-browser.service` daemon ([scripts/live_browser_server.py](./scripts/live_browser_server.py), listening on `127.0.0.1:18795`).

## Key Capabilities

1. **Dual-Mode Telegram Real-Time Visibility**:
   - **In-Chat Live Photo Card (`editMessageMedia`)**: Sends a single `🔴 LIVE 浏览器实况` photo message in the active session owner's verified private DM chat when an explicit `(owner_bot, owner_uid)` session owner is bound (unowned sessions remain localhost CLI only). Telegram `/browser` status queries, profile listings, and mutation errors redact active session details and profile catalogs (`profiles: []` on restricted/group `/internal/status` and `/internal/profiles`, fixed safe group error copy without echoing active profile names or backend errors) for non-owners, unowned CLI sessions, and all non-private group/supergroup deliveries regardless of whether the caller is the owner. Initial card creation via `sendPhoto` verifies explicit `bot_key`, live `admin` RBAC, and `(owner_bot, owner_uid)` before sending and records the returned positive Telegram `message_id`; existing-card control callbacks (`refresh`, `takeover`, `handback`, `stop`) require a positive `message_id` and re-verify `(owner_bot, owner_uid, session_gen)` inside operation locks, while periodic updates edit existing recorded cards (which hold positive `message_id`s from `sendPhoto`). Retired and orphaned cards use strictly stateless fixed copy and empty keyboards without reading newer session metadata; stale/retiring card records are isolated in `pending_retire_cards` keyed by `(bot_key, chat_id, message_id)` so both explicit `retire_cards()` (covering caption-only `editMessageCaption` and final-JPEG `editMessageMedia` paths) and periodic `tick_updates()` / `_tg_maintenance_loop` share the same Telegram retirement response verification (`ok=true` or permanent terminal errors) and per-card `retire_attempts` retry counter (retaining transient `429`/5xx/network failures across paths, fast same-owner session rollovers / new-card publishes, rejected stale-card callbacks, and subsequent `idle`/no-frame or active maintenance ticks up to a shared 3-attempt cap before removing the record). Every outbound retirement/orphan-card Telegram request re-verifies live `admin` RBAC immediately before sending, so bounded retries apply only while authorization remains valid: on live RBAC revocation (including mid-batch or in-flight `sendPhoto` revocation), all active and pending-retire cards for that `(bot_key, chat_id)` are dropped immediately without further Telegram requests, and explicit `mark_finished=False` likewise clears matching active/pending-retire records without calling Telegram. Hosted `stop_hosted()` synchronously advances both generations, switches to `idle`, and clears owner/caches inside `_engine_lock` before bounded button release, async card retirement, and browser teardown.
   - **Telegram Mini App Real-Time Stream (Adaptive Target ~8–12 FPS)**: When a public `https://` URL (`public_url`) is configured, attaches a `[🖥 打开实时画面 / 人工接管]` `web_app` button to the live card. Inside Telegram's built-in Mini App panel, the owner watches adaptive binary JPEG frames (targeting ~8–12 FPS depending on network/client throughput rather than a guaranteed constant FPS, with separate normal/HD frame deduplication, quality presets, atomic tab metadata commits that discard stale snapshots across tab switches and same-page navigations, and monotonic `frameRenderGen` canvas clearing on disconnect/auth-reject/session switch), sharp `(0, 0)`-anchored human & AI arrow cursors with delicate click rings, tabs, native dialogs/file uploads/downloads, and request-level `req_id` `takeover_ack` URL navigation (each new submit or handback invalidates older pending intents, and stale ACKs with `takeover_gen < state.takeover_gen` are ignored).
2. **3-State Human Takeover Arbitration (`👀 观看` -> `🖐 一键接管` -> `▶️ 交还给 AI`)**:
   - When the user clicks **`🖐 一键接管`** in the Mini App (or the agent runs `live-browser wait-human`), AI actions pause cleanly behind a serialized `_takeover_lock` + `_exec_lock` + `ai_allowed_event` execution barrier. Remote WS `input`, `extract`, and `set_takeover` messages must supply explicit valid ASCII integer `(session_gen, takeover_gen)`, and remote WS `start_browser`, `switch_profile`, and `stop_browser` messages must supply an explicit valid ASCII integer `session_gen` matching the current hub generation (missing, boolean, non-ASCII/unparseable such as `"²"`, or stale generations are cleanly rejected/dropped without auto-filling or disconnecting the WebSocket). `set_takeover` validates both generations inside `_takeover_lock`; remote `start`/`switch` actions re-verify live `admin` RBAC, ownership, and generation inside `_engine_lock` at entry, again (along with `idle`, `session_gen`, target `owner`, and startup-phase popup guard status) before publishing a newly launched context (closing it fail-closed on revocation/failure), and again after `await broadcast_state()` before `page.goto(url)`; remote `stop` re-verifies live `admin` RBAC, ownership, and generation inside `_engine_lock` before teardown. Multi-step inputs (`mousedown`, `click`, `type` replace/submit, `clear_field`, `new_tab`, `close_tab`) re-verify `(session_gen, takeover_gen, owner, live admin RBAC)` across await boundaries and re-verify before final capture and before final `broadcast_state`; `new_tab` defers active tab switching during `ctx.on("page")` until post-await checks pass and closes revoked or unguarded pages via deduplicated per-page fail-closed cleanup outside `_exec_lock` (isolating child cleanup cancellation from the service-level `_input_loop` consumer so concurrent `stop_hosted()` never terminates subsequent input handling), while `switch_tab`, `close_tab`, `_current_page`, and tab metadata share the unified `_visible_pages()` set.
   - **Smart Mobile & Desktop Typing**: In **Hosted** mode, clicking an editable `<input>` / `<textarea>` / `[contenteditable]` on the remote canvas pops up a top-aligned Floating Input Sheet (`input_focused`, positioned with `visualViewport` tracking to mitigate iOS keyboard overlap; Sync regular `click` does not emit the same `input_focused` event), supporting full Chinese/Unicode (`insert_text`), password masking, and 1-tap `填入并回车 ↵` / `覆盖原内容`. Desktop physical keyboards also type directly into the active browser page.
   - **Cross-System Copy-Paste (Browser -> Phone/PC System Clipboard, Notes/Notepad, `.txt`, TG)**:
     - **Zero-Fingerprint X11 Clipboard Polling**: Periodically polls Camoufox's underlying Xvfb `DISPLAY` `CLIPBOARD` externally via `xclip -o -selection clipboard -t UTF8_STRING` for value changes (rather than injecting persistent webpage JS hooks or firing instantaneously on every click). When a changed clipboard value is observed after copying on a remote site (e.g. `[Copy]` or `Ctrl+C`/`Cmd+C`), `#clip-sheet` opens in the Mini App.
     - **Freeform Drag-to-Select & Touch Text Extraction (`🖊 选字` / `🖊 拖选文字`)**: Works in both Watch (`👀`) and Takeover (`🖐`) modes (for authorized session owners). Dragging a finger across the canvas paints character ranges via `document.caretPositionFromPoint` (`mode="range"` / `mode="range_preview"`, generation-guarded against canceled previews) with a live top preview pill (`#live-sel-pill`), while single-tapping extracts the element/paragraph (`mode="point"` with container-margin heuristic and sensitive `<input>` masking for password/card/OTP fields in both hosted and sync modes). Hosted `extract` enforces `(session_gen, takeover_gen, owner)` coherence before committing to `latest_clip` and re-verifies `(session_gen, takeover_gen, owner, live RBAC)` post-await before replying; Sync `extract` binds `(req_id, session_gen, takeover_gen, owner)` end-to-end across forwarding, pending tracking, and `/internal/sync/clipboard` reply validation (strictly requiring valid integer `session_gen` and `takeover_gen` in the request body whenever `req_id` is non-empty, rejecting missing/unparseable values with `400`), writing `latest_clip` only after full validation succeeds and sending strictly to the originating live WebSocket (dropping replies if the originating WS disconnected rather than broadcasting to other connections). Users can also expand `#clip-textarea` (`🔍 放大选词`) and sub-select words with native mobile cursor handles (`✂️ 仅复制选中的 X 个字`, blur-safe via `selectionchange`).
     - **Multi-Target Export (Subject to Client WebView / OS Capabilities)**: 1-tap `📋 复制框内全部 / ✂️ 仅复制选中的 X 个字` (`navigator.clipboard` / fallback copy where permitted by the client WebView/OS), `📤 备忘录/分享` (`navigator.share` where supported by the platform), `💾 .txt` file download, or `📨 发回TG`.
   - When the user clicks **`▶️ 交还给 AI`**, queued human commands are drained and held mouse buttons are released: **Hosted** mode awaits `mouse.up` completion under `_exec_lock` before resuming AI, whereas **Sync** mode enqueues trusted server-internal cleanup `mouseup` commands for the local producer to execute on its next poll/checkpoint.
3. **Multi-Fingerprint, Multi-Egress Profiles, Dedicated Multi-Google Isolation & Pinned Host Protection**:
   - **Named Profiles (`~/.config/agy-live-browser/profiles.json`, mode `0600`)**: Create isolated browser identities with per-profile `os` (`windows` / `macos` / `linux`), `locale`, `window` (`WxH`), `webgl_config`, `block_webrtc`, `geoip`, `persistent` / `--ephemeral`, per-profile egress (`--proxy` or memory-only OpenBao `--proxy-bao`), and optional `--allow-google` + `--account <label>` metadata (1..128 chars, no whitespace/control chars; password/secret fields rejected; `account` and profile catalog are redacted to `profiles: []` / stripped for group chats, non-owners, and `readonly` viewers across `/internal/profiles`, `/internal/status`, WS `list_profiles`, `state_dict_for_viewer`, and `_redacted_state_dict`). Forged `pinned: true` flags in `profiles.json` are rejected/stripped, and policy checks never trust bare `pinned=True` or bare `allow_google=True` without canonical host/registry/containment verification.
   - **Zero-Disk Credential Masking**: Proxy credentials are never persisted in plaintext from OpenBao (`--proxy-bao`) and are always masked (`socks5://***@example.com:1080`) in `status`, `profile list`, Telegram cards, and logs.
   - **Pinned Profile Hard-Lock & Dedicated Multi-Google Profiles (Fail-Closed)**: On private hosts where `google-profile` is installed or `AGY_LIVE_BROWSER_REQUIRE_PINNED=1` is set in the service unit, missing/broken `google_browser.py` fails closed with `RuntimeError`, omitting `--profile` or passing `--profile default` resolves to the canonical host-verified pinned persistent profile under `flock` (`headless="virtual"`, `os="windows"`, `humanize=True`, `network.proxy.type=0`, direct egress), and ALL overrides on the pinned profile (`PINNED_FORBIDDEN_OVERRIDES`: `user_data_dir`, `os`, `proxy`, `proxy_bao_ref`, `ephemeral`, `persistent`, `headless`, `persistent_context`, `window`, `locale`, `mobile`, `webgl_config`, `block_webrtc`, `geoip`, `pinned`, `allow_google`, `account`, plus proxy `env`, non-0 `network.proxy.*` prefs, and `allow_override=True`) fail closed with `ValueError` (HTTP `400`).
   - **Unlimited 1:1 Dedicated Google Profiles (`AGY_LIVE_BROWSER_ALLOW_DEDICATED_GOOGLE_PROFILES=1`)**: When the explicit host switch `AGY_LIVE_BROWSER_ALLOW_DEDICATED_GOOGLE_PROFILES=1` is enabled (disabled by default), administrators may create **unlimited** dedicated persistent profiles (`--allow-google`, strictly `persistent=True` and mutually exclusive with `--ephemeral`) for 1:1 account ↔ persistent fingerprint ↔ egress IP isolation, verified against `profiles.json` plus strict non-symlink `PROFILES_DATA_DIR/<name>` containment. To prevent silent drift, launching a dedicated Google profile with fingerprint/egress overrides (`os`, `locale`, `window`, `mobile`, `webgl_config`, `block_webrtc`, `geoip`, `proxy`, `proxy_bao_ref`, proxy `env`, `network.proxy.*` prefs) fails closed with HTTP `400` by default. **Dedicated Google profile fingerprints & egress IPs are NOT permanently locked**: when a residential/proxy egress IP becomes unreachable or needs switching, **after explicit user consent**, update via either:
     - **Path A (Persistent update while `idle`, recommended for long-term node changes)**: `live-browser profile create <name> --overwrite --allow-google --account <label> ...` (`POST /internal/profiles` `overwrite=true`; returns HTTP `409` while the profile is actively running so you must stop it first).
     - **Path B (Explicit launch-time override, for temporary/immediate switching)**: `live-browser start --profile <name> --confirm-override ...` (`POST /internal/start` with strict boolean `allow_override: true`; does not mutate `profiles.json` on disk, while security boundary keys `user_data_dir`, `persistent_context`, `persistent`, `ephemeral`, `pinned`, `allow_google`, `account`, `headless` and the host-pinned profile remain permanently non-overridable).
   - **Ordinary / Ephemeral Non-Google Guard (Fail-Closed)**: On pinned hosts, ordinary (`allow_google=False`), ephemeral (`--ephemeral`), or unverified profiles (and all dedicated profiles when `AGY_LIVE_BROWSER_ALLOW_DEDICATED_GOOGLE_PROFILES` is off) fail closed during startup if Playwright `ctx.route("**/*", ...)`, `ctx.on("page", ...)`, or initial pages' `page.on("framenavigated", ...)` cannot be installed before navigation, abort before publishing if a popup fails guard installation during startup, and quarantine/close subsequent popup or explicit `new_tab` pages whose `framenavigated` registration fails via deduplicated per-page cleanup outside `_exec_lock` (aborting the hosted session under `_engine_lock` with bounded button release if closing fails), blocking direct URLs and Playwright-routed navigations to Google/Gmail/YouTube with a `framenavigated` redirect-to-`about:blank` fallback (within Playwright's engine routing boundary).
   - **Standalone Open-Source Compatibility**: On standalone open-source clones without `google-profile` (or with `AGY_GOOGLE_SKILL_SCRIPTS=""` and `AGY_LIVE_BROWSER_REQUIRE_PINNED` unset), named profiles and the built-in `default` profile work out of the box.
   - Legacy scripts using `with open_google_browser() as ctx:` ALSO stream frames and support interactive human takeover via `SyncLiveBridge`, acting as a trusted localhost producer authenticated with `X-Live-Token`: `internal_sync_start` / `internal_sync_stop` serialize under `_engine_lock`, pinned status requires the local producer's explicit `pinned_launch=True` + matching canonical host `profile_dir` declaration (not runtime context introspection), lease verification enforces built-in TTL expiry without waiting for background ticks, `/internal/sync/push`, `/internal/sync/clipboard`, and `/internal/sync/stop` require header/query `X-Sync-Lease-Id`/`lease_id` before reading the request body and re-check `(lease_id, session_gen)` post-read, server-internal mouseup cleanups use trusted internal queue tags, Sync new tabs open `about:blank` and direct `goto` commands enforce non-pinned Google blocking under local producer policy (not full browser history/redirect interception), and held mouse buttons track their original pressed page (releasing a prior open page before re-pressing the same button on another page, and never falling back to releasing on the current page when the original pressed page is already closed).
4. **Zero-Trust Security & Per-Bot Isolation**:
   - WebSocket `/ws` validates Telegram `WebApp.initData` HMAC-SHA256 at handshake strictly against the signing bot's own whitelist and RBAC role (`admin` / `readonly`), and during initial replay, incoming messages, periodic/broadcast sends, post-await extract responses, and execution-boundary actions re-verifies that the signing bot is still configured, re-reads its live whitelist/RBAC role, and verifies `(owner_bot, owner_uid)` ownership and coherent `session_gen` (rather than re-verifying the initial HMAC on every frame) — closing revoked connections with `auth_error` and WebSocket close code `4003` when revocation is detected (rather than pushing instantaneously upon config file modification). Synchronous page listeners (`dialog`, `filechooser`, `download`, and `framenavigated` Google-block fallback) capture their origin `session_gen` synchronously at listener callback trigger time before scheduling async tasks, while the async `ctx.route` Google-block handler captures `origin_session_gen` at handler entry before its first `await` (and `input_focused` / Sync clipboard & preview broadcasts bind their validated command/request `session_gen`), passing `expected_session_gen` to prevent cross-generation delivery. Active sessions without an explicit `(owner_bot, owner_uid)` owner remain localhost CLI only and return a redacted placeholder to remote WS viewers and Telegram `/browser` status queries.
   - HTTP `/api/upload` and `/api/download/{download_id}` enforce per-bot HMAC auth, live `admin` RBAC, `session_gen` & explicit `(owner_bot, owner_uid)` ownership, pre-disk chooser validation + pre-commit TTL re-check + generation-bound cancellation-safe `filechooser_closed`, decoded HTTP multipart request body byte budgeting (`MAX_UPLOAD_TOTAL_REQUEST_BYTES` = **25 MiB total files + 64 KiB multipart overhead**, enforced via a counting wrapper around aiohttp's `request.content` drained to true EOF including trailing/epilogue bytes before `set_files()`, rather than raw TCP/chunked transport framing), mandatory non-empty `filename` for file parts (`25 MiB` total files, `32 KiB` combined non-file fields, `8 KiB` per non-file field, concurrency 2 in `try/finally`), and a **50 MiB per-file** server-side cache admission cap for downloads (cancels early when response `Content-Length` is observed to exceed 50 MiB and aborts/purges oversized staged files, while the Mini App pre-checks the registered download size rather than independently counting response stream bytes; not a total cache quota, temporary staging quota, or OS-level browser native spool quota; TG DM auto-send remains **20 MiB per file**). Successful download responses (`FileResponse`) include RFC 5987 `Content-Disposition` + `X-Content-Type-Options: nosniff` + `Cache-Control: no-store`, while unauthorized, missing, or oversized requests return JSON `403` / `404` / `413`.

## CLI Usage

```bash
# Check daemon health, active profile/egress/os, takeover lock, and public Mini App URL
live-browser status

# Manage named profiles (multi-fingerprint, multi-egress & dedicated Google profiles)
live-browser profile list
live-browser profile create us-work --os macos --locale en-US --window 1440x900 \
  --block-webrtc --geoip --proxy-bao kv/proxies/us-west
live-browser profile create google-us-1 --allow-google --account acct-us@example.com \
  --os macos --locale en-US --window 1440x900 --block-webrtc --geoip --proxy-bao kv/proxies/us-res
live-browser profile create cf-ephemeral --os linux --ephemeral --proxy socks5://proxy.example.com:1080
live-browser profile delete cf-ephemeral

# Update a dedicated Google profile's egress/fingerprint after explicit user consent:
# Path A (persistent, while idle; returns 409 if running):
live-browser profile create google-us-1 --overwrite --allow-google --account acct-us@example.com \
  --os macos --locale en-US --window 1440x900 --proxy socks5://proxy.example.org:1080
# Path B (temporary launch-time override, does not modify profiles.json):
live-browser start --profile google-us-1 --confirm-override --proxy socks5://proxy.example.net:1080 \
  --url "https://myaccount.google.com"

# Start default (host-pinned persistent direct-egress if installed, else built-in default)
live-browser start --url "https://myaccount.google.com"

# Switch to another profile safely while idle (or stop first)
live-browser start --profile us-work --restart --url "https://example.com"

# Multi-step browser automation (persists across CLI invocations!)
live-browser open "https://mail.google.com/mail/u/0/#inbox"
live-browser click "button[aria-label='Search mail']"
live-browser fill "input[name='q']" "from:cloudflare" --submit
live-browser wait 2000
live-browser text "body"
live-browser screenshot ~/agy-workspace/inbox.png

# Explicitly pause AI and wait for human takeover (background if long!)
# Note: Telegram Live Card interaction requires an (owner_bot, owner_uid) binding and private DM delivery
# (not a hard CLI precondition preventing local wait-human execution)
live-browser wait-human --reason "请在实时面板完成二次确认或人机验证后点【▶️ 交还给 AI】" --timeout 600

# Force-send a new Live Card to the bound session owner's private DM chat
live-browser notify --new

# Configure public HTTPS URL (e.g. Cloudflare Tunnel) for Telegram Mini App button
live-browser set-public-url "https://live.yourdomain.com"

# Close hosted browser and release the profile lock (auto-cleans ephemeral dirs)
live-browser stop
```

## Long-Waiting Takeover Workflow (Telegram Bridge)

When calling `live-browser wait-human` during a Telegram turn (consistent with our project `AGENTS.md` Telegram delivery guidelines):
- **Private DM Ownership Auto-Binding & Group/Cross-Bot Fail-Closed Isolation**: When invoked from a verified Telegram private DM turn (`AGY_BOT_CHAT_ID` set to a strict positive integer, or explicit `--user-id` / `AGY_LIVE_USER_ID`), `live-browser` automatically binds `(owner_bot, owner_uid)` (`source="tg_cmd"`) to the **spawning bridge bot** (`AGY_TG_ENV_FILE` / `AGY_TG_BOT_TOKEN`, default `--bot auto`) across `start`, `stop`, `action`, `update_config`, and `SyncLiveBridge`, ensuring the Live Card and Mini App stream are delivered exclusively to that admin's private DM under the current bot. **Always omit `--bot` during Telegram turns** — explicit cross-bot overrides (`--bot <other>`) inside an active Telegram bridge turn fail closed with `ValueError` instead of misrouting Live Cards into another bot's DM. Negative group/supergroup `AGY_BOT_CHAT_ID` or invalid values never forge a positive `user_id` and fail closed with HTTP `403` without sending cards to groups.
- **Same-Session Human Handover & Bounded Timeout**: Keep the hosted browser session open across `start` -> `wait-human` -> subsequent `open`/`eval`/`text` steps -> `stop` (never cold-start a second Camoufox instance or stop/restart between handover and continuation). Responses include explicit `owner_bound`, `card_sent`, and sanitized `card_error` fields; when `notify=True` and card delivery fails with no active authorized viewer, `wait_human` fails fast instead of hanging. Both hosted `wait_human` and `WrappedSyncPage.wait_for_human(..., timeout=600.0)` enforce positive finite timeouts and generation-guarded `(session_gen, takeover_gen)` takeover cleanup on timeout.
- Run `live-browser wait-human ...` as a **background** command (`WaitMsBeforeAsync <= 5000`), immediately inform the user in chat that they can tap **`[🖥 打开实时画面 / 人工接管]`** on the Live Card above, and let the background command notify you automatically once the user clicks **`[▶️ 交还给 AI]`**!
